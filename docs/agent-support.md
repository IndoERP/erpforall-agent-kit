# How each agent finds skills and instructions

Researched on 2026-11-11 from each vendor's documentation. "Confirmed" means the page says so; "unconfirmed"
means the page does not say, or the pages disagree. **Nothing here was tested by running Codex, Antigravity or
Gemini CLI**; the only local test is `claude plugin validate` (Claude Code 2.1.322), run on this repository.

The kit keeps one source, `skills/<name>/SKILL.md` (Agent Skills format: YAML frontmatter with `name` and
`description`, then Markdown). All three agents read that folder layout, so packaging is mostly a question of
where the folders are linked or copied.

## Claude Code

| Item | Finding | Status |
|---|---|---|
| Skill locations | `~/.claude/skills/<name>/SKILL.md` (personal), `.claude/skills/<name>/SKILL.md` (project), `<plugin>/skills/<name>/SKILL.md` (plugin, invoked as `/plugin-name:skill-name`) | confirmed |
| Frontmatter | `name` (optional, defaults to the directory name) and `description`; `description` plus `when_to_use` are truncated at 1,536 characters in the skill listing; other fields are optional and unknown ones are ignored | confirmed |
| Plugin manifest | `.claude-plugin/plugin.json`; only `name` is required (kebab-case; names starting with `claude-` or `anthropic-` are reserved); `skills/` at the plugin root is scanned by default | confirmed |
| Marketplace | `.claude-plugin/marketplace.json` with `name`, `owner`, `plugins[]`; each entry needs `name` and `source` (a path relative to the marketplace root, or a source object); install with `claude plugin marketplace add <path or owner/repo>` then `claude plugin install <plugin>@<marketplace>` | confirmed (commands not run here) |
| This repository as plugin and marketplace at once (`source: "./"`) | `claude plugin validate .` and `claude plugin validate .claude-plugin/marketplace.json` pass with this repository's files | tested locally |
| Project instructions | `CLAUDE.md` (a `CLAUDE.md` at a plugin root is not loaded as context) | confirmed for the plugin case; not researched further |

Sources: https://code.claude.com/docs/en/skills, https://code.claude.com/docs/en/plugins,
https://code.claude.com/docs/en/plugins/manifest-reference, https://code.claude.com/docs/en/plugins/create-marketplace

Kit choice: `install.sh --agent claude` links the skill folders into `~/.claude/skills` (or `.claude/skills`
with `--scope project`). Alternatively load the repository as a plugin; skills then appear as
`/erpforall-agent-kit:<skill>`. `.claude-plugin/*.json` is generated by `scripts/build-packaging.py`.

## Codex CLI

| Item | Finding | Status |
|---|---|---|
| Skills supported | yes: "Standalone skills are available in the ChatGPT desktop app, Codex CLI, and IDE extension" | confirmed |
| Skill locations | `$CWD/.agents/skills`, `$CWD/../.agents/skills`, `$REPO_ROOT/.agents/skills` (repository), `$HOME/.agents/skills` (user), `/etc/codex/skills` (admin) | confirmed |
| `~/.codex/skills` | not mentioned on the page | unconfirmed (not used by the kit) |
| SKILL.md | must include `name` and `description`; optional `scripts/`, `references/`, `assets/`, and `agents/openai.yaml` for UI metadata and invocation policy | confirmed |
| Symlinks | symlinked skill folders are supported (Codex follows the target) | confirmed |
| Plugins | the page recommends packaging skills as plugins for reuse; the plugin format was not researched | unconfirmed (not used) |
| `AGENTS.md` | global `~/.codex/AGENTS.override.md` or `AGENTS.md` (first non-empty file); then from the project root (usually the Git root) down to the working directory, one file per directory (`AGENTS.override.md`, then `AGENTS.md`); files are joined root first; combined size capped by `project_doc_max_bytes` (32 KiB by default) | confirmed |

Sources: https://learn.chatgpt.com/docs/build-skills (redirect target of https://developers.openai.com/codex/skills),
https://learn.chatgpt.com/docs/agent-configuration/agents-md (redirect target of
https://developers.openai.com/codex/guides/agents-md)

Kit choice: `install.sh --agent codex` links the folders into `~/.agents/skills` (or `<project>/.agents/skills`).
Fallback that certainly works even if skills are not picked up: `install.sh --agents-md` writes a marked block into
the project's `AGENTS.md` that lists the skill files by absolute path; the block is about 5 KiB, well under the
32 KiB cap.

## Antigravity and Gemini CLI

Google's pages say Gemini CLI "was replaced by Antigravity CLI on June 18th, 2026" for some account tiers, so both
are covered.

| Item | Finding | Status |
|---|---|---|
| Antigravity skills (workspace) | `.agents/skills/<name>/SKILL.md`, found in the working folder and each parent up to the repository root; the older `.agent/skills` is still read; subfolders are not searched | confirmed |
| Antigravity skills (personal) | `~/.gemini/config/skills/<name>/SKILL.md` (used by the App and the CLI); the CLI also reads `~/.gemini/antigravity-cli/skills/` and `~/.gemini/skills/` | confirmed |
| Antigravity SKILL.md | `description` required; `name` optional (lowercase letters and hyphens; defaults to the folder name); optional `scripts/`, `examples/`, `resources/` | confirmed |
| Antigravity rules | `AGENTS.md`, `GEMINI.md` and `.agents/rules/*.md` per folder level; global `~/.gemini/AGENTS.md`, `~/.gemini/GEMINI.md`, `~/.gemini/config/rules/*.md`; no stated precedence between `AGENTS.md` and `GEMINI.md` (all are loaded) | confirmed |
| Gemini CLI skills | user `~/.gemini/skills/` or `~/.agents/skills/`; workspace `.gemini/skills/` or `.agents/skills/`; install with `gemini skills install <git URL or path> --consent`, or `/skills link <path>` | confirmed (commands not run) |
| Gemini CLI context files | `~/.gemini/GEMINI.md` plus `GEMINI.md` in workspace folders; other names, such as `AGENTS.md`, through the `context.fileName` setting in `settings.json` | confirmed |
| Extensions / plugins for either | not researched | unconfirmed (not used) |
| Whether Antigravity also reads `~/.agents/skills` | only the Gemini CLI page lists it | unconfirmed |

Sources: https://antigravity.google/docs/customization-discovery?tab=cli,
https://www.antigravity.google/docs/skills, https://geminicli.com/docs/cli/skills/,
https://geminicli.com/docs/cli/gemini-md/

Kit choice: `install.sh --agent antigravity` uses `~/.gemini/config/skills` (user) or `<project>/.agents/skills`
(project); `--agent gemini` uses `~/.gemini/skills` or `<project>/.gemini/skills`. Neither agent needs a
generated file. Because `AGENTS.md` is loaded by Antigravity, the `--agents-md` fallback works there too; Gemini CLI
needs `context.fileName` to include `AGENTS.md`.

## What the kit generates

| File | From | By |
|---|---|---|
| `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` | `VERSION` and the skill list | `scripts/build-packaging.py` |
| `templates/AGENTS.md.snippet` | skill names and descriptions | `scripts/build-packaging.py` |

`scripts/build-packaging.py --check` (run by CI and by the tests) fails when a generated file is out of date.
